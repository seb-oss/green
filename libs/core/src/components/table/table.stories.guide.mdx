## Data Model Structure

### Request Interface

The table sends this request object to your data provider:

```typescript
interface TableRequest {
  page: number              // Current page (1-indexed)
  rows: number              // Rows per page
  sortColumn?: string       // Column key to sort by
  sortDirection?: 'asc' | 'desc'
  searchQuery?: string      // Search term
}
```

### Response Interface

Your data provider must return:

```typescript
interface TableResponse<T> {
  rows: T[]                 // Array of data rows
  total: number             // Total count (for pagination)
}
```

---

## Data Provider Function

The data provider handles fetching, filtering, sorting, and pagination.

### Server-Side Implementation

```typescript
const dataProvider = async (
  request: TableRequest
): Promise<TableResponse<DataRow>> => {
  const response = await fetch('/api/data', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(request),
  })
  
  const data = await response.json()
  
  return {
    rows: data.items,
    total: data.totalCount,
  }
}
```

### Client-Side Implementation

```typescript
const allData: DataRow[] = [
  // Your complete dataset
]

const dataProvider = async (
  request: TableRequest
): Promise<TableResponse<DataRow>> => {
  await new Promise(resolve => setTimeout(resolve, 300))
  
  let processedData = [...allData]
  
  // Apply search filter
  if (request.searchQuery) {
    const query = request.searchQuery.toLowerCase()
    processedData = processedData.filter(row =>
      Object.values(row).some(value =>
        String(value).toLowerCase().includes(query)
      )
    )
  }
  
  // Apply sorting
  if (request.sortColumn) {
    processedData.sort((a, b) => {
      const aValue = String(a[request.sortColumn as keyof DataRow])
      const bValue = String(b[request.sortColumn as keyof DataRow])
      
      return request.sortDirection === 'asc'
        ? aValue.localeCompare(bValue)
        : bValue.localeCompare(aValue)
    })
  }
  
  // Apply pagination
  const startIndex = (request.page - 1) * request.rows
  const endIndex = startIndex + request.rows
  const paginatedData = processedData.slice(startIndex, endIndex)
  
  return {
    rows: paginatedData,
    total: processedData.length,
  }
}
```

## Column Configuration

### Type Imports

All table-related TypeScript types are exported from the component for use in your application:

```typescript
import { Types } from '@sebgroup/green-core/components/table'

// Use the types
const columns: Types.Column[] = [...]
const dataProvider = async (request: Types.Request): Promise<Types.Response<DataRow>> => {...}
```

### Basic Column

A column configuration maps data properties to table columns with display and behavior options.

```typescript
const columns: Types.Column[] = [
  {
    key: 'title',     // Property key in your data row object
    label: 'Title',   // Column header text displayed to users
    sortable: true,   // Enables click-to-sort on column header
    align: 'start',   // Vertical alignment: 'start' | 'center' | 'stretch' | 'end'
    justify: 'start', // Justify content horizontally: 'start' | 'center' | 'space-between' | 'end'
    visible: true,    // Controls column visibility (used on the settings dropdown)
    width: '200px',   // Fixed column width (When set content wraps automatically)
  }
]
```

### Custom Value Extractor

The optional `value` function lets you control what raw value the table uses for display, sorting, and search. This is useful when your row data shape doesn't match a simple key lookup:

```typescript
{
  key: 'fullName',
  label: 'Full Name',
  sortable: true,
  value: (row) => `${row.firstName} ${row.lastName}`,
}
```

## Slot-Based Cell Composition

The table uses a **slot composition model** for rich cell content. Instead of declaring cell types in column configuration, you use the `Slot()` helper and named HTML slots to inject any Green Design System component (or custom HTML) into cells.

This approach gives you full control over cell rendering any component, any layout, any interaction without the table needing to know about the content.

### How It Works

The slot system has three steps:

1. **Wrap cell values** with `Slot()` in your data provider to declare which slots each cell uses
2. **Listen** for the `gds-table-data-loaded` event
3. **Render slot content** into the table's light DOM using named slot elements

### The `Slot()` Helper

Import the `Slot` function from the table component:

```typescript
import { Slot } from '@sebgroup/green-core/components/table/table.types'
```

`Slot()` wraps a cell value and declares slot positions:

```typescript
Slot(value, slots, key?)
```

| Parameter | Type | Description |
|---|---|---|
| `value` | `unknown` | The fallback display value (also used for sorting and search) |
| `slots` | `string[]` | Ordered array of slot IDs that define the cell layout |
| `key` | `string \| number` | Optional custom row key (defaults to `row.id` or row index) |

The special slot ID `'value'` renders the plain text value inline. All other IDs create named `<slot>` elements.

```typescript
// Text value with a trailing copy button
Slot(row.email, ['value', 'copy-button'])
//    ↑ value     ↑ renders text   ↑ renders <slot name="email:{rowKey}:copy-button">

// Only slotted content, no plain text
Slot(row.status, ['status'])
//    ↑ used for sort/search   ↑ renders <slot name="status:{rowKey}:status">

// Leading image, then text value
Slot(row.name, ['avatar', 'value'])
//                ↑ slot        ↑ plain text
```

> `Slot()` objects transparently participate in sorting, searching, and string operations the table uses the `value` parameter for all comparisons.

### Slot Naming Convention

All cell slots follow the pattern:

```
{columnKey}:{rowKey}:{slotId}
```

- **columnKey** The `key` from the column configuration (e.g. `'name'`, `'email'`, `'status'`)
- **rowKey** Resolved in order: custom `Slot` key → `row.id` → row index + 1
- **slotId** The arbitrary string you defined in the `slots` array

### Step 1: Normalize Row Data

Wrap cell values that need rich content with `Slot()`:

```typescript
const normalizeRow = (row: any) => ({
  ...row,
  name:     Slot(row.name, ['avatar', 'value']),       // image + text
  email:    Slot(row.email, ['value', 'copy-button']),  // text + button
  status:   Slot(row.status, ['status']),               // badge only
  amount:   Slot(row.amount, ['amount', 'currency']),   // formatted number + badge
  account:  Slot(row.account, ['main']),                // formatted account
  login:    Slot(row.lastLogin, ['main']),              // formatted date
  download: Slot(row.download ?? '#', ['main']),        // link
})
```

Cells without `Slot()` render as plain text automatically.

### Step 2: Listen for Data Loaded

The table emits `gds-table-data-loaded` after each data fetch. The event detail contains the current page rows. Use this to render slot content into the table's light DOM:

```typescript
table.addEventListener('gds-table-data-loaded', (e) => {
  render(slotContent(e.detail.rows), table)
})
```

### Step 3: Render Slot Content

Create slot elements using the `{columnKey}:{rowKey}:{slotId}` naming convention:

```typescript
const slotContent = (rows) => html`
  ${rows.map((row) => html`
    <!-- name column: avatar image -->
    <gds-img
      slot="name:${row.id}:avatar"
      src="${row.avatarUrl}"
      alt="${String(row.name)}"
      width="xl"
      height="xl"
    ></gds-img>

    <!-- email column: copy button -->
    <gds-button
      slot="email:${row.id}:copy-button"
      rank="tertiary"
      size="small"
    >
      <gds-icon-copy></gds-icon-copy>
    </gds-button>

    <!-- status column: badge -->
    <gds-badge
      slot="status:${row.id}:status"
      variant="${String(row.status) === 'Active' ? 'positive' : 'negative'}"
      size="small"
    >
      ${String(row.status)}
    </gds-badge>

    <!-- amount column: formatted number + currency badge -->
    <gds-formatted-number
      slot="amount:${row.id}:amount"
      .value=${row.amount}
    ></gds-formatted-number>
    <gds-badge slot="amount:${row.id}:currency" size="small">
      SEK
    </gds-badge>

    <!-- account column: formatted account -->
    <gds-formatted-account
      slot="account:${row.id}:main"
      account="${row.account}"
      format="seb-account"
    ></gds-formatted-account>

    <!-- login column: formatted date -->
    <gds-formatted-date
      slot="login:${row.id}:main"
      .value="${String(row.login)}"
      locale="sv-SE"
      format="dateLong"
    ></gds-formatted-date>

    <!-- download column: link with icon -->
    <gds-link
      slot="download:${row.id}:main"
      href="${row.download ?? '#'}"
      text-decoration="underline"
      download
    >
      Download file
      <gds-icon-cloud-download slot="trail"></gds-icon-cloud-download>
    </gds-link>
  `)}
`
```

### Multiple Slots in a Single Cell

A cell can have multiple slot positions. The order in the `slots` array controls the layout order:

```typescript
// Image on the left, text in the middle, badge on the right
Slot(row.name, ['avatar', 'value', 'verified-badge'])
```

```html
<gds-img slot="name:${row.id}:avatar" src="${row.avatar}" width="xl" height="xl"></gds-img>
<gds-badge slot="name:${row.id}:verified-badge" variant="positive" size="small">Verified</gds-badge>
```

### Multiple Elements in a Single Slot

Multiple elements can share the same slot name. They render in DOM order within that slot position:

```html
<!-- Two buttons sharing the same slot -->
<gds-button slot="actions:${row.id}:main" rank="tertiary" size="small">
  <gds-icon-pin></gds-icon-pin> Activate
</gds-button>
<gds-button slot="actions:${row.id}:main" rank="tertiary" size="small">
  <gds-icon-cross-small></gds-icon-cross-small> Delete
</gds-button>
```

## Actions Column

The `actions` property defines an actions column rendered as the last cell of each row.

### Configuration

When passed as an object, it configures the column header. Action content is provided through slots:

```typescript
const actions: Types.Actions = {
  label: 'Actions',
  justify: 'end',
}
```

### Action Slot Content

The actions column uses `actions:{rowKey}:main` as its slot name:

```typescript
const actionSlotContent = (rows) => html`
  ${rows.map((row) => html`
    <gds-context-menu slot="actions:${row.id}:main">
      <gds-button slot="trigger" rank="tertiary" size="small">
        <gds-icon-dot-grid-one-horizontal></gds-icon-dot-grid-one-horizontal>
      </gds-button>
      <gds-menu-item>Edit ${String(row.name)}</gds-menu-item>
      <gds-menu-item>Delete</gds-menu-item>
    </gds-context-menu>
  `)}
`
```

### Actions as a Render Function

Alternatively, pass a function that returns a template for each row. This skips the slot system entirely:

```typescript
const actions = (row, index) => html`
  <gds-button rank="tertiary" size="small" @click=${() => edit(row)}>
    Edit
  </gds-button>
`
```

## Framework Integration

The table is a web component that works across all frameworks. The key pattern is the same everywhere:

1. Configure columns and data provider
2. Normalize rows with `Slot()`
3. On `gds-table-data-loaded`, render slot content into the table element

Below are full working examples for each framework.

<details>
<summary><strong>Lit</strong></summary>

```typescript
import { LitElement, html } from 'lit'
import { customElement, state } from 'lit/decorators.js'
import { createRef, ref } from 'lit/directives/ref.js'
import { render } from 'lit'

import '@sebgroup/green-core/components/table'
import '@sebgroup/green-core/components/badge'
import '@sebgroup/green-core/components/context-menu'
import '@sebgroup/green-core/components/icon/icons/dot-grid-one-horizontal'
import '@sebgroup/green-core/components/formatted-text/number'
import '@sebgroup/green-core/components/formatted-text/date'

import { Slot, Types } from '@sebgroup/green-core/components/table'

interface UserRow {
  id: number
  name: string
  email: string
  status: 'Active' | 'Inactive'
  amount: number
  date: string
}

@customElement('my-user-table')
export class MyUserTable extends LitElement {
  private tableRef = createRef<any>()

  private columns: Types.Column[] = [
    { key: 'id',     label: 'ID' },
    { key: 'name',   label: 'Name',   sortable: true },
    { key: 'email',  label: 'Email',  sortable: true },
    { key: 'status', label: 'Status', sortable: true },
    { key: 'amount', label: 'Amount', sortable: true, justify: 'end' },
    { key: 'date',   label: 'Date',   sortable: true },
  ]

  private actions: Types.Actions = {
    label: 'Actions',
    justify: 'end',
  }

  private normalizeRow(row: UserRow) {
    return {
      ...row,
      status: Slot(row.status, ['badge']),
      amount: Slot(row.amount, ['formatted']),
      date:   Slot(row.date, ['formatted']),
    }
  }

  private dataProvider = async (
    request: Types.Request
  ): Promise<Types.Response<any>> => {
    const response = await fetch('/api/users', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(request),
    })
    const data = await response.json()
    return {
      rows: data.items.map((row: UserRow) => this.normalizeRow(row)),
      total: data.totalCount,
    }
  }

  private slotContent(rows: any[]) {
    return html`
      ${rows.map((row: any) => html`
        <gds-badge
          slot="status:${row.id}:badge"
          variant="${String(row.status) === 'Active' ? 'positive' : 'negative'}"
          size="small"
        >${String(row.status)}</gds-badge>

        <gds-formatted-number
          slot="amount:${row.id}:formatted"
          .value=${row.amount}
        ></gds-formatted-number>

        <gds-formatted-date
          slot="date:${row.id}:formatted"
          .value="${String(row.date)}"
          locale="sv-SE"
          format="dateLong"
        ></gds-formatted-date>

        <gds-context-menu slot="actions:${row.id}:main">
          <gds-button slot="trigger" rank="tertiary" size="small">
            <gds-icon-dot-grid-one-horizontal></gds-icon-dot-grid-one-horizontal>
          </gds-button>
          <gds-menu-item>Edit</gds-menu-item>
          <gds-menu-item>Delete</gds-menu-item>
        </gds-context-menu>
      `)}
    `
  }

  private handleDataLoaded(e: CustomEvent) {
    const table = this.tableRef.value
    if (table) render(this.slotContent(e.detail.rows), table)
  }

  render() {
    return html`
      <gds-table
        ${ref(this.tableRef)}
        .columns=${this.columns}
        .actions=${this.actions}
        .data=${this.dataProvider}
        rows="10"
        searchable
        settings
        selectable
        density="comfortable"
        @gds-table-data-loaded=${(e: CustomEvent) => this.handleDataLoaded(e)}
      ></gds-table>
    `
  }
}
```

## Complete Example

A full example with row normalization, slot content, and table configuration:

```typescript
import { html, render } from 'lit'

import '@sebgroup/green-core/components/table'
import '@sebgroup/green-core/components/badge'
import '@sebgroup/green-core/components/img'
import '@sebgroup/green-core/components/context-menu'
import '@sebgroup/green-core/components/formatted-text/number'
import '@sebgroup/green-core/components/formatted-text/date'
import '@sebgroup/green-core/components/formatted-text/account'
import '@sebgroup/green-core/components/icon/icons/dot-grid-one-horizontal'
import '@sebgroup/green-core/components/icon/icons/copy'
import '@sebgroup/green-core/components/icon/icons/cloud-download'

import { Slot, Types } from '@sebgroup/green-core/components/table'

// ── Data shape ──────────────────────────────────────────────
interface UserRow {
```

## Custom State Slots
The table provides three slots to customize empty and error states. Each slot has a default fallback that displays if no custom content is provided.

**Available slots:**
- `error` Shown when the data provider throws an error
- `empty` Shown when the data provider returns zero rows with no active search
- `no-results` Shown when the data provider returns zero rows with an active search query

**Example:**
```html
<gds-table .columns=${columns} .data=${dataProvider} searchable>
  <!-- Error state -->
  <gds-flex slot="error" flex-direction="column" gap="s">
    <gds-text font="heading-s">Unable to load data</gds-text>
    <gds-text font="detail-book-m">
      An error occurred. Please try again.
    </gds-text>
    <gds-button size="small" @click=${retry}>Retry</gds-button>
  </gds-flex>

  <!-- Empty state (no data at all) -->
  <gds-flex slot="empty" flex-direction="column" gap="s">
    <gds-text font="heading-s">No data available</gds-text>
    <gds-text font="detail-book-m">
      There are no records to display.
    </gds-text>
  </gds-flex>

  <!-- No results state (search returned nothing) -->
  <gds-flex slot="no-results" flex-direction="column" gap="s">
    <gds-text font="heading-s">No matches found</gds-text>
    <gds-text font="detail-book-m">
      Try different search terms.
    </gds-text>
    <gds-button size="small" @click=${clearSearch}>
      Clear Search
    </gds-button>
  </gds-flex>
</gds-table>
```

### Static Layout Slots

| Slot Name | Purpose |
|---|---|
| `header-lead` | Content at the start of the table header bar (after search input) |
| `header-trail` | Content at the end of the table header bar (before settings dropdown) |

## Reactive Properties

The `page` and `rows` properties are fully reactive changing them from outside the component (via attribute, property binding, or JavaScript) will automatically sync internal state and trigger a data fetch.

### Page

Setting `page` navigates to the specified page and loads the corresponding data.

```html
<!-- Attribute -->
<gds-table page="3" .columns=${columns} .data=${dataProvider}></gds-table>

<!-- Property binding (Lit) -->
<gds-table .page=${currentPage} .columns=${columns} .data=${dataProvider}></gds-table>
```

```js
// Programmatic
const table = document.querySelector('gds-table')
table.page = 5 // Navigates to page 5 and loads data
```

### Rows

Setting `rows` changes the number of rows per page. This resets to page 1 since changing page size invalidates the current page position.

```html
<!-- Attribute -->
<gds-table rows="25" .columns=${columns} .data=${dataProvider}></gds-table>

<!-- Property binding (Lit) -->
<gds-table .rows=${rowsPerPage} .columns=${columns} .data=${dataProvider}></gds-table>
```

```js
// Programmatic
table.rows = 50 // Shows 50 rows per page, resets to page 1
```

### Other Reactive Properties

| Property | Triggers | Notes |
|---|---|---|
| `page` | Data fetch for the new page | |
| `rows` | Data fetch, resets to page 1 | Page size change invalidates position |
| `data` | Cache clear + data fetch | New data provider |
| `dataLoadKey` | Cache clear + data fetch | Force reload with a new key value |
| `columns` | Cache clear + view reset | Resets visible columns and pagination |

## Best Practices

### Performance
- Use server-side pagination for large datasets (>1000 rows)
- Implement debouncing for search queries
- Cache responses when appropriate
- The table caches data provider responses for 5 minutes by default (keyed on page/rows/sort/search). Use `nocache` to disable.

### Column Configuration
- Keep column count reasonable (5-10 visible)
- Use `width` for columns with long content
- Enable sorting only on indexed columns
- Use `justify="end"` for numeric columns

### User Experience
- Use `searchable` boolean to enable search for the data
- Use `settings` to let users customize columns
- Use `selectable` for bulk actions
- Provide clear empty and error states

## Migration Guide: Cell Types to Slots

This section helps you migrate from the **old cell type configuration** (where cell types were declared in column definitions) to the **new slot composition model**.

### What Changed

The old approach embedded cell rendering logic directly in column configuration using a `cell` property with predefined types (`badge`, `button`, `link`, `image`, `context-menu`, `formatted-number`, etc.). The table component itself was responsible for rendering all cell types.

The new approach moves cell rendering **out of the table** and into your application via web component slots. The table only provides slot insertion points you control what components render in each cell.

**Benefits of the new approach:**
- Use **any** Green Design System component or custom HTML in cells
- No dependency on predefined cell types the table doesn't need to know about your content
- Compose multiple components in a single cell with full control over order
- Simpler table internals, better tree-shaking

### Quick Comparison

<details>
<summary><strong>Side-by-side: Old vs New</strong></summary>

**Old cell types in column config:**
```typescript
const columns = [
  {
    key: 'status',
    label: 'Status',
    sortable: true,
    cell: {
      value: {
        type: 'badge',
        value: (row) => row.status,
        variant: (row) => row.status === 'Active' ? 'positive' : 'negative',

    }
  }

```

```typescript

```

### Step-by-Step Migration

#### 1. Remove `cell` from Column Definitions

Strip the `cell` property from all column configurations. Keep `key`, `label`, `sortable`, `align`, `justify`, `visible`, and `width`.

```diff
  {
    key: 'status',
    label: 'Status',
    sortable: true,
-   cell: {
-     value: {
-       type: 'badge',
-       value: (row) => row.status,
-       variant: (row) => row.status === 'Active' ? 'positive' : 'negative',
-     }
-   }
  }
```

#### 2. Add Row Normalization with `Slot()`

Create a function that wraps cell values needing rich content with `Slot()`.

For each column that previously had a `cell` configuration, decide which slot IDs you need:

```typescript
import { Slot } from '@sebgroup/green-core/components/table/table.types'

const normalizeRow = (row) => ({
  ...row,
  // Previously: cell.value.type = 'badge'
  status: Slot(row.status, ['badge']),

  // Previously: cell.value.type = 'formatted-number' + trail badge
  amount: Slot(row.amount, ['formatted', 'currency']),

  // Previously: cell.lead.type = 'image', cell.value = plain text
  name: Slot(row.name, ['avatar', 'value']),

  // Previously: cell.value = plain text, cell.trail.type = 'button'
  email: Slot(row.email, ['value', 'copy-btn']),
})
```

#### 3. Update Your Data Provider

Call `normalizeRow` on each row in your data provider response:

```diff
  const dataProvider = async (request) => {
    const response = await fetch('/api/data', { ... })
    const data = await response.json()
    return {
-     rows: data.items,
+     rows: data.items.map(normalizeRow),
      total: data.totalCount,
    }
  }
```

#### 4. Create Slot Content Renderer

Write a function that generates the slot HTML for each row:

```typescript
const slotContent = (rows) => html`
  ${rows.map((row) => html`
    <!-- Map each old cell type to its GDS component with slot attribute -->
    ...
  `)}
`
```

#### 5. Wire Up the Data Loaded Event

Add an event listener for `gds-table-data-loaded` and render slot content:

```diff
  <gds-table
    .columns=${columns}
    .data=${dataProvider}
+   @gds-table-data-loaded=${(e) => {
+     render(slotContent(e.detail.rows), tableElement)
+   }}
  ></gds-table>
```
